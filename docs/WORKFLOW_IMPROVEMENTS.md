# 0.1.5 工作流优化

## 文案生成

超长文案先交给 AI 压缩表达，再检查标题、正文、话题和已填写的比赛条件。最多改写两次；仍不合格时显示原因，不截断正文结尾。档位范围、报名费用、台费和赛程按填写内容保留。条件过长时请缩短条件，或选择容量更大的模板。

批量生成每组最多 5 条，检查相似标题、开头和正文，自动补齐不足的条数。界面显示完成数与目标数；达到重试上限或遇到连续错误时保留已完成内容，可以点击「补齐缺少的文案」。费用条件的校验比较保守，改写时要求原样保留，避免改动范围或费用含义。

客户端、服务端和前端容量清单统一来自 `shared/template-catalog.json`。修改清单后需要同步生成 `frontend/template-catalog.js`；`node scripts/check-frontend.mjs` 会检查两份内容一致。

## 批量出图

同类任务运行期间禁止重复启动，事件使用独立任务编号。可以取消任务；渲染时会先完成当前图片保存，再停止后续图片。AI 生成取消后不再继续发出新请求；已经发给服务端的请求可能仍会在服务端完成。

成功、失败和未处理请求分别记录，重试只处理失败与未完成项。渲染进度每张写入本地数据库，重新打开后可以继续上一次任务。进度检查点保留最近 20 次任务；文件写入与检查点之间发生进程强制退出时，最后一张图片可能需要核对输出目录。

每张 PNG 同目录附带同名 TXT，包含对应标题、正文、话题和模板。批量文案超出容量时先提示处理，避免直接省略关键条件。

## 模板与草稿

模板画廊提供真实原生渲染缩略图，支持按名称搜索、分类筛选和收藏。缩略图按可见区域加载，不阻塞主预览。通用卡片模板支持短文案自动增大字号、收紧话题与卡片区域；独立版式保留各自布局。

草稿自动保存单条、批量文案、提示词和非敏感配置；下方状态栏显示保存进度。重新打开后恢复草稿。可以保存最多 20 个常用配置，复用地区、人设、比赛条件、模板、配色与数量分配。常用配置不替换当前正文；应用配置时更新已有提示词。

草稿字段有明确允许列表，不包含 API Key、账号密码或登录令牌。草稿、常用配置与收藏保存在本机，不随现有云同步上传。

## 文案库

文案库支持跨全部记录搜索、分类、收藏、编辑、删除和每页 50 条分页。当前筛选可以导出 CSV 与 JSON，最多 10000 条，保存到输出目录中的独立导出文件夹。

分类与收藏通过文案内容关联，在云端下载重新建立本地行号后仍能保留。分类和收藏仅在本机保存；「删除」删除本地文案，不删除现有云端副本。图片与对应文案通过保存图文的 PNG/TXT 文件对导出。

## 验证与发布

客户端测试覆盖关键条件保留、真实 HTTP 改写请求、重复文案、任务隔离、取消标记、草稿允许字段、文案库筛选，以及长短文案渲染边界。服务端使用同一份容量与文案规则并独立测试。

界面回归使用隔离的本地 IPC 测试数据，缩略图与图片由真实 Rust 渲染器生成；没有调用用户的 AI 接口、密钥或数据库。Windows 构建执行客户端、服务端测试与 Clippy，再生成安装包。服务端源代码已更新，发布桌面客户端不会自动部署线上 API。
