# macOS 云端化原型施工清单

## 目标

以现有 macOS Tauri + Rust 应用为原型，增加账号、云端配置同步和服务器 AI 网关，同时保留本地 Rust 渲染能力。

本阶段不实现 Windows 和 Android 客户端，但所有服务接口、数据模型和本地存储边界要为后续跨平台复用做好准备。

## 总体边界

- [ ] 客户端继续使用 Rust + SVG + `resvg` 本地生成 `1080 x 1920` PNG。
- [ ] 服务器负责账号、用户配置、文案库同步和 AI 请求转发。
- [ ] DeepSeek、通义、Kimi 等供应商 API Key 只存在服务器，不下发到客户端。
- [ ] 默认不上传图片；图片继续保存到 macOS 本地输出目录。
- [ ] 无网络时仍可使用模板预览、渲染和保存；需要账号或 AI 的功能显示明确状态。
- [ ] 本阶段不做支付、会员、公开图库、社交关系和多租户管理员后台。

## 推荐架构

```text
macOS Tauri 客户端
  ├─ Rust 本地渲染器
  ├─ 本地 SQLite 缓存
  └─ Keychain 保存登录会话
          │ HTTPS
          ▼
Rust API 服务（Axum）
  ├─ 账号与设备会话
  ├─ 配置和文案库同步
  ├─ AI Provider 网关
  └─ 限流、用量和审计
          │
          ├─ PostgreSQL
          └─ 服务器 Secret / 环境变量
```

## 0. 基线冻结与备份

- [ ] 为当前 macOS 版本建立基线标签，例如 `macos-local-v0.1`。
- [ ] 备份旧版 `settings.json`、`accounts.json`、文案库和输出目录。
- [ ] 记录现有数据库结构、Keychain service/account 和应用 identifier。
- [ ] 确认现有本地渲染、批量渲染、历史和迁移测试全部通过。
- [ ] 明确服务器地址、数据库部署位置和开发环境配置，不把密钥写入仓库。

## 1. 服务端工程骨架

- [ ] 新建独立服务目录，例如 `server/`，与 Tauri 客户端分开编译。
- [ ] 使用 Rust Axum 建立 HTTP 服务和统一错误响应格式。
- [ ] 增加 `/health`、版本信息和服务启动日志。
- [ ] 配置开发、测试、生产三套环境变量。
- [ ] 强制 HTTPS；开发环境允许本机 HTTP，生产环境禁止明文请求。
- [ ] 增加 PostgreSQL 连接池、迁移工具和启动时迁移检查。
- [ ] 所有请求设置超时、请求体大小限制和结构化日志。

## 2. 账号系统 MVP

- [ ] 选择登录方式：邮箱 + 密码作为第一版，不在客户端保存密码。
- [ ] 用户密码使用 Argon2id 或同等级密码哈希，禁止明文保存。
- [ ] 实现注册、登录、刷新会话、退出当前设备和退出全部设备。
- [ ] 使用短时 access token + 可撤销 refresh token。
- [ ] refresh token 只保存哈希值，记录设备名称、创建时间、最后使用时间。
- [ ] 客户端 Keychain 保存会话凭据，SQLite 不保存明文 token。
- [ ] 登录失败限速，连续失败返回统一错误，不泄露账号是否存在。
- [ ] 预留邮箱验证和找回密码接口，但不阻塞本地原型开发。

## 3. 服务端数据模型

- [ ] `users`：用户、状态、创建时间、最后登录时间。
- [ ] `sessions`：refresh token 哈希、设备信息、过期时间、撤销时间。
- [ ] `user_settings`：API 服务选择、模型、输出偏好和界面偏好，不存供应商 Key。
- [ ] `accounts`：用户的账号人设、区域、档位、性格和语气。
- [ ] `presets`：用户预设及版本时间戳。
- [ ] `copy_library`：标题、正文、标签、来源和更新时间。
- [ ] `usage_records`：AI 调用次数、字数、耗时和结果状态，不记录 API Key。
- [ ] 所有业务表带 `user_id`，查询和更新必须强制带当前用户条件。
- [ ] 为用户数据增加软删除或可恢复备份策略。

## 4. AI 网关

- [ ] 服务端实现统一接口：单条文案、批量文案和提示词生成。
- [ ] Provider 适配器支持 OpenAI 兼容协议，先接入一个供应商完成闭环。
- [ ] API Key 只从服务器 Secret Manager 或环境变量读取。
- [ ] API Key 不出现在响应、普通配置、日志、错误信息和数据库业务表中。
- [ ] 设置连接超时、整体超时、有限次数重试和供应商错误映射。
- [ ] 对用户输入做长度限制，避免无限制请求和意外高额用量。
- [ ] 批量请求限制数量，返回逐条成功、失败和可重试状态。
- [ ] 记录用量元数据，不记录完整提示词和敏感内容，除非用户明确开启历史保存。
- [ ] 客户端断网、服务端超时和供应商限流都显示可理解的中文提示。

## 5. macOS 客户端接入

- [ ] 设置页增加服务器地址、登录、退出登录和当前账号状态。
- [ ] 登录后将 access/refresh 会话存入 macOS Keychain。
- [ ] 客户端启动时只读取本地会话状态，不自动打印 token 或请求 API Key。
- [ ] 将现有 `generate_copy`、`generate_batch_copy` 改为调用服务器 AI 网关。
- [ ] 保留本地渲染 IPC：`render_preview`、`render_save`、`render_batch` 不经过服务器。
- [ ] 增加“同步设置”“上传文案库”“下载文案库”动作和同步时间提示。
- [ ] 本地 SQLite 作为离线缓存，服务端数据带版本号或更新时间。
- [ ] 首次登录提供“上传本机数据 / 使用云端数据 / 稍后处理”选择，禁止静默覆盖。
- [ ] 注销时清除本机 session 和同步缓存，但不删除本地图片和用户明确保留的数据。
- [ ] 网络不可用时禁用云端按钮，模板预览和本地出图继续可用。

## 6. 同步规则

- [ ] 先采用“手动同步 + 最后写入者优先”，避免第一版引入复杂冲突合并。
- [ ] 每条可同步记录包含 `id`、`updated_at`、`deleted_at` 和 `version`。
- [ ] 同步失败不丢本地数据，保留未同步状态和重试入口。
- [ ] 文案库重复项按稳定 ID 去重，不按标题猜测覆盖。
- [ ] API Key 不参与同步；服务器 Key 与本地旧 Key 明确分离。

## 7. 安全与运维

- [ ] 生产环境使用 TLS、严格 CORS、基础安全响应头和 CSRF 防护（如使用 Cookie）。
- [ ] API 路由按认证、用户资源和管理员资源分层保护。
- [ ] AI 接口按用户限流，并设置单日或单分钟调用上限。
- [ ] 日志脱敏：token、Key、完整请求头和用户敏感内容不得落盘。
- [ ] 数据库每日备份，并至少完成一次恢复演练。
- [ ] 增加服务可用性、AI 错误率、延迟和用量监控。
- [ ] 服务器密钥轮换流程可执行，不依赖重新发布客户端。

## 8. 测试验收

- [ ] 注册、登录、刷新、退出和过期会话测试通过。
- [ ] 两个用户互相不能读取或修改对方的设置、账号和文案库。
- [ ] 单条 AI 文案成功、超时、限流和供应商错误均有正确提示。
- [ ] 批量 AI 文案部分失败时能保留成功项并显示失败项。
- [ ] 断网时 6 套模板预览、保存和批量本地渲染通过。
- [ ] 首次登录上传本地数据、下载云端数据和取消操作均不丢数据。
- [ ] 升级客户端后 Keychain、SQLite、本地输出目录和历史记录仍可用。
- [ ] macOS Intel release 包在无开发工具的机器上完成安装和首次启动。
- [ ] 日志和数据库扫描确认没有 API Key、refresh token 或密码。

## 9. macOS 原型交付物

- [ ] 服务端开发环境启动说明和 `.env.example`。
- [ ] 数据库迁移文件和初始化说明。
- [ ] macOS 客户端登录版 `.app` 和 `.dmg`（本阶段可不签名）。
- [ ] 一份账号、同步、AI 网关和离线渲染的验收记录。
- [ ] 一份服务器备份、密钥轮换和故障排查说明。
- [ ] GitHub 中不包含真实 API Key、数据库密码、证书、Token 或生产数据。

## 本阶段完成标准

当以下流程全部通过，macOS 云端化原型即完成：

1. 用户在 macOS 客户端注册或登录。
2. 客户端可以同步账号配置和文案库。
3. AI 文案请求经过服务器完成，客户端看不到供应商 API Key。
4. 无网络时仍可本地渲染、保存和查看历史。
5. 重新安装或升级后，登录状态、设置和本地输出数据按预期保留。
6. 两个账号之间没有数据越权，日志和数据库中没有密钥泄露。
